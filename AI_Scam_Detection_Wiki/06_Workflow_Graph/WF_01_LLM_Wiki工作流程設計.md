# WF_01：LLM Wiki 工作流程設計

## 一、工作流程目的

本專題使用 Obsidian 建立 AI 網路詐騙偵測系統的 LLM Wiki，並搭配 ChatGPT 整理知識，最後產生教學型 HTML 簡報。

整體流程分成資料取得、Wiki 查詢、內容整理、品質檢查及 HTML 產生五個主要階段。

## 二、Workflow 流程設計

```
flowchart TD
    A([開始]) --> B[取得五篇原始資料]
    B --> C[匯入 Obsidian Wiki]
    C --> D[查詢相關知識]
    D --> E[整理教學重點]
    E --> F{內容檢查}
    F -->|通過| G[產生 HTML 簡報]
    F -->|未通過| H[找出錯誤或缺漏]
    H --> D
    G --> I{簡報檢查}
    I -->|通過| J([完成])
    I -->|未通過| K[修改簡報內容]
    K --> G
```

## 三、各節點功能說明

### 節點 1：資料取得

取得至少五篇與 AI 網路詐騙偵測相關的資料。

資料範圍：

- 網路詐騙基本概念
    
- 假投資詐騙案例
    
- AI 網路詐騙偵測技術
    
- NLP 自然語言處理
    
- 機器學習與釣魚網站偵測
    

### 節點 2：Wiki 知識庫建立

將資料整理成 Markdown 筆記，匯入 Obsidian。

透過資料夾分類管理原始資料、知識筆記及工作流程。

### 節點 3：查詢 Wiki

利用 ChatGPT 根據 Wiki 中的資料查詢相關內容。

查詢項目：

- 詐騙的基本定義
    
- 常見詐騙手法
    
- AI 偵測技術
    
- NLP 的應用
    
- 機器學習分類方法
    

### 節點 4：整理重點

將查詢結果整理成適合初學者理解的教學內容。

整理原則：

1. 先介紹基本概念。
    
2. 再介紹常見詐騙案例。
    
3. 接著介紹 AI 偵測技術。
    
4. 最後說明系統架構及研究限制。
    

### 節點 5：內容檢查

在產生簡報前檢查：

- 是否符合原始資料內容？
    
- 是否有錯誤或不合理的描述？
    
- 是否有未經證實的實驗數據？
    
- 是否有標示資料來源？
    
- 是否適合初學者閱讀？
    

如果未通過，返回 Wiki 查詢及重點整理階段。

### 節點 6：產生 HTML 簡報

使用 ChatGPT 根據整理完成的內容產生 HTML 教學簡報。

預計包含：

- 封面
    
- 網路詐騙基本概念
    
- 常見詐騙案例
    
- AI 偵測技術
    
- NLP 與機器學習
    
- AI 防詐系統架構
    
- 系統限制
    
- 結論
    

### 節點 7：簡報檢查

檢查 HTML 是否可以正常開啟及瀏覽。

檢查項目：

- 投影片切換功能
    
- 文字及圖片顯示
    
- 內容是否完整
    
- 來源是否正確
    
- 頁面是否有排版錯誤
    

若有問題，修改 HTML 後重新檢查。

## 四、Loop 設計

本專題設計兩個主要迴圈：

### Loop 1：知識內容修正

當內容檢查不通過時，重新查詢 Wiki、整理資料及修正錯誤。

目的：避免錯誤資訊直接進入簡報。

### Loop 2：HTML 簡報修正

當 HTML 出現排版、內容或功能問題時，重新修改及產生簡報。

目的：確保最後的簡報可以正常使用。

## 五、為什麼使用 Loop / Graph？

如果採用一次性生成，AI 可能產生錯誤內容、遺漏資料來源，或出現不符合教學需求的內容。

透過檢查節點及重新生成機制，可以在不同階段發現問題，減少錯誤累積。

Graph 負責定義整體工作流程，Loop 則負責處理未通過檢查的內容。

## 六、預期成果

完成一套以 Obsidian 為知識庫、ChatGPT 為內容整理工具的 LLM Wiki 工作流程，並利用整理完成的知識產生 HTML 教學簡報。

# AI 網路詐騙偵測系統－Loop / Graph 工作流程設計

## 一、工作流程目的

本專案使用 Obsidian 建立 AI 網路詐騙偵測系統 LLM Wiki，將網路詐騙基本概念、詐騙案例、AI 偵測技術及相關研究資料整理成知識庫，再利用知識庫產生教學型 HTML 簡報。

## 二、Workflow 流程

1. **取得資料（Data Collection）**
    
    - 蒐集至少五篇網路詐騙與 AI 偵測相關資料。
        
    - 優先使用政府機關及研究資料。
        
2. **資料匯入（Ingest）**
    
    - 將資料整理成 Markdown 筆記。
        
    - 分類存放於 Obsidian 的 Original Sources。
        
3. **知識整理（Knowledge Processing）**
    
    - 整理常見詐騙手法。
        
    - 分析 AI 偵測技術。
        
    - 建立 Knowledge Notes。
        
4. **查詢 Wiki（Wiki Retrieval）**
    
    - 從 Obsidian 知識庫查詢相關內容。
        
    - 依照簡報主題取得所需資訊。
        
5. **整理簡報大綱（Content Planning）**
    
    - 將資料轉換成教學順序。
        
    - 由基本概念逐步介紹 AI 偵測方法。
        
6. **內容檢查（Verification）**
    
    - 檢查內容是否符合原始資料。
        
    - 確認技術名稱、案例及資料來源。
        
    - 發現錯誤時返回知識整理或簡報大綱重新修正。
        
7. **產生 HTML 簡報（HTML Generation）**
    
    - 將確認後的內容製作成 HTML。
        
    - 加入上一頁、下一頁及全螢幕功能。
        
8. **測試與修正（Testing）**
    
    - 使用瀏覽器開啟 HTML。
        
    - 檢查頁面、文字、操作及顯示效果。
        
    - 有問題時返回修改並重新測試。
        

## 三、Loop 設計

本專案採用循環式工作流程。

當內容檢查發現資料錯誤時，返回知識整理階段；當簡報顯示或操作異常時，返回 HTML 生成階段重新修改。

重複執行「整理 → 檢查 → 修正」，直到內容正確且簡報可以正常瀏覽。

## 四、Graph 設計

主要節點：

- Data Collection
    
- Ingest
    
- Knowledge Notes
    
- Wiki Retrieval
    
- Content Planning
    
- Verification
    
- HTML Generation
    
- Testing
    

節點之間透過資料來源及知識連結形成關係，讓原始資料能夠追溯至最後的簡報內容。

## 五、設計原因

採用此流程可以降低 AI 產生錯誤資訊的風險，也能讓簡報內容有原始資料作為依據。

透過 Loop 反覆檢查及修正，可以提高資料正確性與簡報品質。
## 六、實際執行與反思

### 1. 哪一個節點最常出錯？

我認為最容易出錯的是「整理重點與產生簡報」節點。因為 AI 在整理不同來源資料時，可能會遺漏重要資訊，或將一般詐騙特徵與 AI 偵測技術混在一起，造成簡報內容不夠精確。

### 2. 發現問題後，把檢查往前移到哪個步驟？

我將檢查提前到「查詢 Wiki 與整理重點」階段，先確認資料是否來自原始資料來源，並檢查內容是否符合知識庫中的記載，再進行簡報生成。

### 3. 是否修改 Workflow / Graph？為什麼？

有。我在原本的流程中加入資料驗證與內容檢查節點。如果發現資料不完整或內容有誤，就返回知識庫重新查詢與整理，而不是直接產生 HTML 簡報。

這樣可以減少錯誤累積，提升簡報內容的正確性與可信度。
